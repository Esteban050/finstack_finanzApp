## Criterio de clasificación — REGLA CENTRAL

¿La petición o respuesta problemática es una que el front legítimo envía o espera según el contrato existente?
- Si el front envía algo fuera de contrato (etiqueta en vez de valor, campos de más, formato distinto, valor que el propio selector ofrece pero el servidor no cataloga), el defecto es del FRONT. Lo corriges tú. En el documento de backend queda, como mucho, como DESEABLE: "el servidor podría tolerar/ignorar/explicar X". Nunca como error del backend.
- Es DEFECTO DE BACKEND solo si: (1) se reproduce con una petición conforme al contrato, o con una petición directa que el front no origina, y (2) viola un RF/RNF/RN literal, la seguridad o la integridad, independientemente de lo que haga el front.
- Ante la duda, es Deseable, no Defecto.
